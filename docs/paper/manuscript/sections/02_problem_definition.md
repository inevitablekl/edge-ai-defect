# 1 系统对象与问题定义

## 1.1 模型、数据集与边缘部署平台

本文研究对象为部署于 NVIDIA Jetson Orin Nano Super 边缘计算平台的 YOLOv8n 工业缺陷检测模型。实验环境实际记录为 L4T R36.5、CUDA 12.6、TensorRT 10.3 和 OpenCV 4.5.4，模型输入尺寸固定为 640×640，批量大小为 1。NVIDIA 官方资料显示，JetPack 6.2.2 所含 Jetson Linux 36.5、CUDA 12.6 和 TensorRT 10.3 与本文实际记录的组件版本相对应；本文的平台环境身份仍以实测组件版本为准，不据此将 JetPack meta-package 版本作为独立实测身份 [@nvidia_jetpack_6_2_2]。检测网络采用 YOLOv8n，其模型身份以及目标检测、模型导出等基本能力以 Ultralytics 官方文档为依据 [@ultralytics_2023_yolov8_docs]。

实验数据来源于东北大学钢材表面缺陷数据资源。其原始表面缺陷数据库包含轧制氧化皮、斑块、开裂、点蚀表面、夹杂和划痕 6 类缺陷，共 1 800 幅 200×200 灰度图像 [@song_yan_2013_neu_surface_defects]。本文使用项目冻结的 NEU-DET 目标检测标注数据及固定测试集。历史数据划分中训练集、验证集和测试集分别包含 1 260、360 和 180 幅图像，后续核查发现训练集与验证集之间存在 1 个内容重复样本。去重后的划分调整为 1 260、359 和 180 幅，测试集成员保持不变；匹配条件下模型选择排序亦未发生变化。因此，本文后续部署实验均采用去重后的数据划分和同一组 180 幅测试图像，不以数据划分调整引入新的模型训练或模型转换结果。

在推理精度方面，本文采用既有 YOLOv8n 模型，通过 TensorRT 校准式 INT8 后训练量化（post-training quantization，PTQ）构建后续实验固定使用的混合精度 Engine，构建过程中同时启用 INT8 和 FP16 精度选项。PTQ 的基本特点是在已有训练模型基础上实施低比特量化，而非重新进行量化感知训练 [@kim_lee_kim_2024_hyq]。在固定的 180 幅测试图像上，该 INT8 Engine 的 mAP50-95 为 0.352 3，相对 FP16 结果下降 0.007 2。本文据此将该 Engine 作为后续数据路径实验的固定推理对象，而不把 INT8 量化方法本身作为本文的算法创新。需要指出的是，本文采用的校准式 INT8 路线对应 TensorRT 10.3 环境中的历史接口体系，相关隐式量化和 calibrator 接口在该版本已被标记为弃用，因此本文结论仅针对冻结的软件栈与实验对象 [@nvidia_tensorrt_10_3_release_notes]。

## 1.2 端到端推理数据路径与受控变量

目标检测的模型执行主要指固定输入张量进入 TensorRT Engine 后的网络计算，而部署执行路径还包括图像获取与解码、原始图像暂存、预处理、必要的数据移动、推理同步、后处理和结果构造。已有 Jetson 部署研究也将目标检测过程划分为预处理、模型推理和后处理等阶段，并指出在轻量化模型部署中，仅优化网络推理本身不能完整反映系统数据路径的性能特征 [@tang_qian_2024_yolov8_jetson_orin]。因此，本文不改变模型执行对象，而是在保持模型、INT8 Engine、输入尺寸、测试数据和后处理语义不变的条件下，将预处理执行位置和主机暂存内存类型定义为受控的系统变量。

如图1所示，本文定义 3 条正式比较的受控系统路径。基线路径 V0 采用主机源数据/主机张量路径，并通过 CPU/OpenCV 完成主要像素级预处理，随后向 TensorRT INT8 设备输入提供数据。V2R 使用可分页主机内存（pageable host memory）作为原始图像暂存区，并采用与 OpenCV 4.5.4 语义对齐的 CUDA 预处理。相对于 V0，V2R 同时改变主要像素级预处理的执行位置及其相关输入准备与数据路径，属于本文实验设计中的较宽范围干预。V3R 则保持 V2R 的 CUDA 预处理语义、模型、Engine、后处理和执行拓扑不变，仅将原始图像暂存区替换为锁页主机内存（pinned host memory），因而 V2R→V3R 是只改变主机暂存内存分配类型的较窄范围干预。这里的宽、窄描述的是受控变量所覆盖的路径范围，不是对各阶段性能贡献的因果分解。

CUDA 官方文档指出，锁页主机内存能够为主机与设备之间的数据传输提供较高带宽，但锁页内存本身属于有限资源，其实际应用收益仍需要结合具体数据路径进行测量 [@nvidia_cuda_best_practices_12_6]。因此，本文不预设 pinned memory 必然改善系统性能，而是将其作为单独变量进行受控比较。与此同时，CUDA 对内存、流和同步机制的通用支持仅用于说明相关实现语义 [@nvidia_cuda_programming_guide_12_6]，不能据此推定本文 V3R 存在跨帧异步重叠、双缓冲或多流并行。3 条路径的具体结构见图1。

## 1.3 端到端性能模型与优化覆盖范围

为描述网络推理之外的完整执行对象，本文将统一计时区间内的端到端耗时概念化表示为

\[
T_{\mathrm{E2E}}
=
\sum_{k=1}^{m} T_k .
\]

其中，\(T_k\) 表示定义的 E2E 计时区间内与某一执行阶段相关的耗时贡献，可在概念上对应数据源图像获取与解码、原始图像暂存、预处理、必要的数据移动、TensorRT 推理与同步、后处理以及结果对象构造。该式用于明确研究对象由多个执行环节共同组成，不表示本文对各个 \(T_k\) 进行了独立插桩或测量，也不提供任何未实测的阶段耗时。

在受控路径比较中，进一步将路径 \(v\) 的端到端耗时抽象为

\[
T_v
=
T_{\mathrm{common}}
+
T_{\mathrm{specific},v},
\qquad
v\in\{V0,V2R,V3R\}.
\]

式中，\(T_{\mathrm{common}}\) 表示实验设计中有意保持共同的执行组成，\(T_{\mathrm{specific},v}\) 表示随路径配置变化的执行部分。该表示仅用于说明控制变量和干预层级，并不声称两个项在实验中被分别计时。由此，V0→V2R 覆盖主要像素级预处理执行位置及其相关输入准备数据路径，是较宽范围干预；V2R→V3R 保持 CUDA 预处理语义及下游执行不变，只改变主机原始图像暂存的分配类型，是较窄范围干预。

局部优化对整体性能的作用还可借助 Amdahl 型覆盖关系进行概念解释：

\[
S_{\mathrm{E2E}}
=
\frac{1}
{(1-\alpha)+\alpha/S_{\mathrm{opt}}}.
\]

其中，\(\alpha\) 表示抽象执行工作量中受到优化影响的比例，\(S_{\mathrm{opt}}\) 表示经典理想化关系中受影响部分的加速比，\(S_{\mathrm{E2E}}\) 表示由此得到的整体理论加速比。本文只用该关系解释“优化覆盖范围会约束整体收益”这一系统思想，不从 V0/V2R 或 V2R/V3R 的实测结果反求、拟合或估计 \(\alpha\)，也不据此预测 Jetson 上的实际加速比。真实执行路径还包含该简化关系未表达的内存、运行时与同步效应，因此本文不主张实测系统严格满足 Amdahl 模型假设。上述三个公式均为实验设计和结果讨论的解释框架，而不是实测数据的定量拟合模型。

## 1.4 统一计时边界与研究问题

推理系统的延迟与吞吐率描述不同的性能属性，且尾延迟需要结合明确的测试场景和百分位统计方式进行报告。MLPerf Inference 等系统基准研究针对不同推理场景分别采用百分位延迟、受延迟约束的吞吐率和离线吞吐率等指标，说明仅报告单一模型推理时间不足以完整描述推理系统性能 [@reddi_et_al_2019_mlperf_inference]。本文并不采用 MLPerf 的查询生成、样本数或统计置信规则，而是在固定离线回放工作负载下使用项目自身统一冻结的测量协议。

为保证 3 条数据路径的可比性，本文定义统一的外部逐帧计时区间。计时起点位于获取数据源帧之前，区间内包含图像获取与解码、不同路径对应的原始数据暂存、CPU 或 CUDA 预处理、必要的主机到设备数据传输、TensorRT INT8 推理及同步、需要的设备到主机传输、后处理与非极大值抑制（non-maximum suppression，NMS）以及帧结果对象构造；计时终点位于结果对象构造完成之后、结果序列化和写文件之前。JSON 序列化、文件 I/O、摘要信息持久化以及结果摘要校验信息的最终写入均不计入该逐帧延迟计时区间。

统一测试协议中，每次独立运行首先执行 60 帧预热，随后测量 1 080 帧，即对固定 180 幅测试图像完成 6 个完整回放周期；每种路径执行 5 个独立进程，共形成 15 次有效运行。3 条路径均关闭内部逐帧诊断计时和 profiling，使逐帧延迟采用同一外部计时机制。逐帧平均延迟以及 P95、P99 延迟由统一的 source-to-pre-sink 外部计时样本统计，而帧率则根据各独立运行的测量帧数与 measured process-wall 时间计算，两类指标采用不同的统计边界；具体聚合方法在实验设计部分进一步说明。

基于上述统一对象与测量边界，本文重点考察两个逐级隔离的问题：首先，在固定 INT8 推理对象和统一 source-to-pre-sink 外部逐帧计时区间内，V0→V2R 这一较宽范围干预对 FPS、平均延迟及尾延迟产生何种变化；其次，在 CUDA 预处理语义保持不变的情况下，V2R→V3R 这一较窄范围干预对平均性能和 P95、P99 尾延迟产生何种增量影响，以及平均行为与尾部行为是否呈现一致方向。由此，后续比较均限定在 V0、V2R 和 V3R 的共同实验合同内，不将不同模型、不同推理后端或不同实验协议下获得的加速比进行组合，也不把概念上的覆盖范围解释为阶段级因果贡献。
