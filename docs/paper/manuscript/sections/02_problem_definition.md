# 1 输入数据路径模型与问题表述

## 1.1 固定推理对象与系统边界

本文将检测器、Engine、输入尺寸、工作负载与后处理语义的组合记为固定推理对象，具体配置与工作负载见表2。三条路径的置信度阈值、IoU阈值、候选框上限和class-aware单标签后处理均不变；平台与软件版本仅为实验条件，不属于路径变量。

系统边界采用单帧顺序执行：从获取数据源帧前开始，经图像解码、输入形成、主机—设备数据移动、Engine推理与同步、输出回传、CPU后处理和结果构造，至结果序列化及写文件前结束。该边界不包含跨帧流水线、显式传输/计算重叠、多流执行、zero-copy或GPU NMS。

## 1.2 路径描述符与名义复制载荷

固定推理对象不唯一决定模型输入如何到达Engine，输入路径仍需决定跨边界表示、输入张量形成位置、额外打包原始图像的主机暂存组织和执行拓扑。三条路径的总体结构及层级受控比较关系见图1。基于这四类决策，将路径表示为

\[
P=(R,F,M,E),
\]

式（1）中，\(R\)表示跨越主机—设备边界的数据表示，\(F\)表示TensorRT输入张量的形成位置，\(M\)表示额外打包原始图像的主机暂存策略，\(E\)表示执行拓扑。预处理位于CPU或GPU是\(F\)的实现映射，而非额外引入的独立控制变量。该描述符只用于识别比较中发生改变与保持受控的结构变量，不是延迟预测模型，也不用于分解各变量的延迟贡献。

由\(R\)可推导每帧名义输入复制载荷

\[
B(P)=H_R(P)W_R(P)C_R(P)s_R(P).
\]

其中，\(H_R,W_R,C_R,s_R\)分别为跨边界表示的高、宽、通道数与单元素字节数。实例化后，\(B(P_0)=640\times640\times3\times4=4.9152\ \mathrm{MB/frame}\)，\(B(P_2)=B(P_3)=200\times200\times3\times1=0.1200\ \mathrm{MB/frame}\)，因而\(B(P_0)/B(P_2)=40.96\)。该比值是由表示结构得到的名义载荷对比，不是实测总线或DRAM流量、带宽、H2D时间或传输加速比。

表1将描述符实例化。\(P_0\)对应V0：\(R\)为FP32 NCHW张量，\(F\)在主机侧，\(M\)无额外打包原始图像暂存；\(P_2\)对应V2R：\(R\)为packed BGR uint8，\(F\)在设备侧，\(M\)为pageable；\(P_3\)对应V3R，其余变量与\(P_2\)相同，仅\(M\)改为pinned。三者的\(E\)均为单帧顺序执行。

**表1　三条输入数据路径的结构描述与派生量。名义输入复制载荷由跨边界表示推导，非实测流量。**

| 路径描述项 | V0（\(P_0\)） | V2R（\(P_2\)） | V3R（\(P_3\)） |
|---|---:|---:|---:|
| H2D数据表示 \(R\) | FP32 NCHW张量 | packed BGR uint8 | packed BGR uint8 |
| 输入张量形成位置 \(F\) | 主机 | 设备 | 设备 |
| 预处理位置 | CPU | GPU融合处理 | GPU融合处理 |
| 额外打包原始图像暂存策略 \(M\) | 无 | Pageable | Pinned |
| 名义输入复制载荷 \(B(P)\)/(MB/frame) | 4.9152 | 0.1200 | 0.1200 |
| 执行拓扑 \(E\) | 单帧顺序 | 单帧顺序 | 单帧顺序 |

## 1.3 层级受控比较、正确性条件与评价问题

如图1所示，干预层级依据受控结构变量的范围划分：\(P_0\rightarrow P_2\)同时改变跨边界表示和张量形成位置，并引入相应的原始图像暂存，即\(R,F,M\)发生变化而\(E\)保持不变，属于耦合的路径级重构；\(P_2\rightarrow P_3\)在\(R,F,E\)保持不变时只改变\(M\)，属于局部暂存策略细化。该层级不预设收益大小、组件重要性或瓶颈关系，也不构成阶段级因果分解。

**图1　输入数据路径抽象及层级受控比较。图中层级表示结构变量的干预范围，不表示收益大小或组件级因果关系。**

性能比较以同一工作负载、评价器、模型/Engine、输入与后处理语义下的任务正确性保持为准入条件，核验结果见4.1节。该条件只保证冻结工作负载和评价口径内的可比性，不表示逐位相等或对未来输入普适等价。

完整路径的直接测量响应定义为

\[
T_{\mathrm{E2E}}(P)=t_{\mathrm{pre\text{-}sink}}(P)-t_{\mathrm{source}}(P),
\]

其中，\(t_{\mathrm{source}}\)位于获取数据源帧前，\(t_{\mathrm{pre\text{-}sink}}\)位于结果构造完成且序列化和写文件前。本文评价完整路径\(P\)的E2E响应，不独立测量H2D、预处理或CUDA核函数时间。

据此提出：RQ1，在固定推理对象、工作负载和任务语义时，\(P_0\rightarrow P_2\)路径级重构对完整E2E平均响应产生何种影响？RQ2，在\(R,F,E\)、GPU预处理语义及下游结构保持不变时，\(P_2\rightarrow P_3\)只改变主机暂存策略，是否产生额外平均响应，以及P95/P99是否呈现一致改善？RQ1由4.2节回答，RQ2由4.3和4.4节回答。
