# 3 实验设计

## 3.1 实验平台与模型配置

实验在 NVIDIA Jetson Orin Nano Super 平台上完成。实际记录的软件环境为 L4T R36.5、CUDA 12.6.11（runtime 12.6.68）、TensorRT 10.3.0.30 和 OpenCV 4.5.4。检测模型固定为 YOLOv8n，输入尺寸为 640×640，batch size 为 1；推理后端采用第1节所述冻结 TensorRT INT8 混合精度 Engine。在 V0、V2R 和 V3R 的正式比较过程中，不重新构建或重新校准 Engine，也不改变模型、输入尺寸、检测阈值和后处理配置。正式执行中，3 条路径使用相同的 Engine、模型合同和测试数据身份。

本文实验对象与统一运行条件如表1所示。

## 3.2 数据集与统一运行协议

性能实验采用第1节所述 split-v2 固定测试集，共 180 幅图像。为保证不同数据路径处理相同的输入序列，每次独立运行均使用同一测试 manifest 和相同图像顺序。正式测量前先执行 60 帧预热，预热结束后完成必要同步并重置正式测量窗口；随后测量 1080 帧，相当于对 180 幅测试图像连续回放 6 个完整周期。每条数据路径执行 5 个独立进程，因此 V0、V2R 和 V3R 各获得 5400 个正式逐帧延迟样本。

为降低固定执行位置可能带来的时间顺序偏差，15 个独立进程按照预先冻结的交错顺序执行。5 组顺序依次为：V0–V2R–V3R、V3R–V2R–V0、V2R–V0–V3R、V0–V3R–V2R 和 V2R–V3R–V0。该顺序在运行前确定，不根据中间性能结果进行随机替换、跳过或重新排序。正式执行中 15 个进程均按照该顺序完成。

3 条路径采用相同的模型、Engine、输入 manifest、输入尺寸、batch、检测阈值、NMS 参数和输出合同，配置间唯一有意变化的是数据路径类型。每次正式运行要求处理帧数与请求帧数一致、丢帧数为0，并正常完成流结束及必要同步；不满足协议、身份、帧数、顺序或生命周期检查的运行不得进入汇总。正式比较同时关闭内部逐帧诊断计时和 profiling，使不同数据路径均采用统一外部测量机制。正式证据显示 15 次运行均满足上述有效性条件。

## 3.3 正确性和性能指标

本文将正确性验证与性能统计分别处理。V2R 的任务级正确性评价使用固定的 180 幅测试图像，以相同检测配置下的 V0 任务级结果作为参考。评价指标包括 precision、recall、mAP50 和 mAP50-95，并同时检查类别级 AP50 和 recall 差异。总体 mAP50-95、mAP50、precision 和 recall 的允许绝对差异分别为 0.005、0.005、0.010 和 0.010，类别级最大 AP50 和 recall 差异阈值分别为 0.020 和 0.030。V3R 不执行第二次独立的任务级参数选择，而是在 V2R 已确定的 CUDA preprocessing semantic 下，通过张量/检测摘要、帧顺序、处理计数、丢帧和 EOS 等信息验证 companion identity。该分层方法保持任务级正确性与实现身份验证的含义不同。

性能评价包括帧率（frames per second，FPS）、逐帧平均延迟以及 P95、P99 延迟。推理系统中的 latency、throughput 和 tail-latency 描述不同的性能属性，百分位指标应与具体测量场景和统计边界共同解释 [@reddi_et_al_2019_mlperf_inference]。本文不采用 MLPerf 的查询生成或置信度规则，而仅采用其对不同性能指标应分别定义的测量思想。

FPS 与逐帧 latency 使用不同统计边界。对第 \(i\) 个独立运行，FPS 定义为

\[
f_i=\frac{N}{T_i},
\]

其中 \(N=1080\) 为正式测量帧数，\(T_i\) 为该运行记录的 measured process-wall 时间，单位为 s。该 process-wall 区间包围一次完整的 measured run，并包含正式运行中统一的结果 sink/output processing，其边界不同于在结果序列化和写出之前结束的逐帧 source-to-pre-sink latency 区间。因此 FPS 不是由逐帧 latency 样本取倒数得到，两类指标也不具有相同的计时边界。

每种路径的平均帧率由 5 个独立运行的 FPS 算术平均得到：

\[
\bar f=\frac{1}{5}\sum_{i=1}^{5}f_i .
\]

FPS 的离散程度仅使用这 5 个进程级 FPS 值计算样本标准差（sample standard deviation）：

\[
s_f=\sqrt{\frac{\sum_{i=1}^{5}(f_i-\bar f)^2}{5-1}} .
\]

因此后续 FPS 图中的误差量表示 5 次独立运行 FPS 的样本标准差，不表示置信区间，也不用于统计显著性推断。

逐帧延迟采用第1节定义的统一 source-to-pre-sink 外部计时边界。每种路径将 5 次有效运行的 1080 个测量帧合并为 \(n=5400\) 个延迟样本，平均延迟由全部 5400 个样本直接求算术平均，而不是先计算 5 个 run mean 后再次平均。P95 和 P99 也在同一 5400 样本池上计算，并采用冻结的 Type-7 线性插值百分位定义。设升序样本为 \(x_{(1)},\ldots,x_{(n)}\)，对于概率 \(p\)，令

\[
h=1+(n-1)p,\qquad
j=\lfloor h\rfloor,\qquad
\gamma=h-j,
\]

则内部位置的百分位数为

\[
Q_p=(1-\gamma)x_{(j)}+\gamma x_{(j+1)}.
\]

分别取 \(p=0.95\) 和 \(p=0.99\) 得到 P95 与 P99。Phase 1 冻结指标 provenance 将 P95 和 P99 定义为对每种路径全部 5400 个逐帧延迟样本采用 Type-7 线性插值计算；后续 mean、P95 和 P99 均以 ms 为单位报告。

所有性能结果均作为上述固定工作负载下的描述性统计量报告。本文不新增置信区间、假设检验或显著性判断，也不将 FPS 与其他阶段的 throughput 指标互换使用。V0、V2R 和 V3R 的比较只在本节定义的统一实验合同内成立。
