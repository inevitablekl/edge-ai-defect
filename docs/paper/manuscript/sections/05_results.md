# 4 结果与分析

## 4.1 正确性验证结果

在比较不同数据路径的性能之前，首先验证 CUDA 预处理路径是否保持既有检测任务语义。正确性验证是后续性能解释的前提：只有受测路径满足预设的语义与正确性条件，观察到的性能差异才可在本文控制边界内解释为路径配置间的差异。V2R 以相同的 180 幅测试图像和 V0 任务级结果为基准进行正确性评价，结果如表2所示。

**表2　V0与V2R任务级正确性验证结果**

| 指标 | V0 | V2R | 绝对差异 | 允许差异 | 结果 |
|---|---:|---:|---:|---:|---|
| Precision | 0.6913 | 0.6913 | 0 | 0.010 | 通过 |
| Recall | 0.6991 | 0.6991 | 0 | 0.010 | 通过 |
| mAP50 | 0.6476 | 0.6476 | 0 | 0.005 | 通过 |
| mAP50-95 | 0.3523 | 0.3523 | 0 | 0.005 | 通过 |

除表2中的总体指标外，类别级最大 AP50 和 recall 绝对差异也均为0，分别低于预设的0.020和0.030阈值。由此可见，在当前180幅测试图像及既定检测配置下，V2R 的任务级检测结果满足预先设定的正确性判据。这里的结论仅针对任务级评价，不扩展为原始推理张量的逐元素或比特级等价。

V3R 不进行第二次独立的任务级正确性验收，而是在 V2R 已确定的 CUDA 预处理语义基础上进行伴随一致性验证。180幅图像的帧顺序、路径和几何信息均通过检查，运行过程中无丢帧，能够正常完成流结束和资源回收；预处理张量摘要和检测结果摘要均与 V2R 一致，检测数量均为447。因此，V3R 的验证结果支持其作为仅改变主机暂存内存类型的伴随路径参与后续性能比较，但不将该一致性验证解释为独立任务级正确性评价。

## 4.2 CUDA预处理的主要性能收益

从实验设计看，V0→V2R 同时改变主要像素级预处理执行位置及其相关输入准备数据路径，涉及的结构与配置范围宽于只改变主机暂存分配类型的 V2R→V3R。该描述用于区分两级受控变量，不表示已测得受影响执行时间的比例，也不由结构范围预测实际性能收益。

观测结果如图2所示，其中误差棒表示每种路径5次独立运行 FPS 的样本标准差。V0 的平均帧率为54.600 FPS，样本标准差为0.223 FPS；采用 pageable 主机暂存和 CUDA 预处理的 V2R 达到122.122 FPS，样本标准差为0.492 FPS。V2R 相对于 V0 的帧率比为2.236671×，即 FPS 提高123.6671%。

**图2　V0、V2R和V3R平均帧率比较**

逐帧延迟观测如图3所示。V0 的平均延迟、P95和P99分别为18.273、18.854和19.068 ms；V2R 分别降低至8.140、9.827和11.529 ms。按照预设的成对比较口径，V2R 相对于 V0 的平均延迟降低55.4519%，P95和P99分别降低47.8780%和39.5385%。

**图3　V0、V2R和V3R平均及尾延迟比较**

在当前受控配置下，主要 E2E 性能增益出现在 V0→V2R 比较中。已有其他 AI 推理系统研究表明，预处理及相关数据管理可能成为完整流水线中的系统级性能因素 [@lee_han_kim_2025_presto]。本文观测与这一一般解释相容，而不是只反映固定 INT8 Engine 的网络执行；在固定模型、INT8 Engine、测试数据和统一计时条件下，从 V0 切换至 V2R 后，平均帧率提高，平均及尾部延迟降低。

这一解释仍受证据边界约束。V0→V2R 同时改变主要像素级预处理执行位置及其相关输入准备与数据路径，实验未分别测量 resize、颜色转换、布局转换、归一化或单次数据传输的耗时。因此，2.236671× FPS 比和55.4519%平均延迟降低属于完整 V2R 受测路径的观测结果，不能分配为某个 CUDA kernel、某项像素操作或某次主机—设备传输的独立因果贡献；本文也不据此估计受影响执行时间的比例。

## 4.3 Pinned内存的增量收益

从实验设计看，V2R→V3R 只改变原始图像主机暂存区的内存分配类型，CUDA 预处理语义、TensorRT Engine、后处理及执行拓扑均保持不变，因而属于比 V0→V2R 结构上更窄的路径干预。这一结构描述不等同于受影响执行时间比例的测量，也不预先判断增量大小。

观测结果显示，V3R 的平均帧率为127.097 FPS，对应5次独立运行 FPS 的样本标准差为1.279 FPS；其逐帧平均延迟为7.812 ms。与 V2R 相比，V3R 的 FPS 提高4.0738%，平均延迟降低4.0349%。

在这一结构上较窄的变化下，实验仅观察到有限的平均性能增量。已有集成 CPU/GPU 和 GPU 内存分配研究表明，不同内存策略的性能表现依赖具体平台、工作负载和访问特征 [@bateni_et_al_2020_integrated_memory; @rodriguez_et_al_2025_gpu_memory_allocation]。本文观测与这种非普适性相容；局部优化的 E2E 作用仍取决于实际受影响执行比例，而本文没有测量该比例。在当前离线回放工作负载和执行拓扑下，改变主机暂存分配类型后，V3R 在 V2R 已取得的主要收益基础上进一步改善平均性能，但增量幅度小于 V0→V2R 的完整路径变化。

证据层面只能确认本文受测完整路径中 pageable 与 pinned staging 的平均性能差异。由于未对内存分配、主机复制或主机—设备传输分别计时，不能将4.0349%的平均延迟降低解释为 pinned memory 独立节省的时间，也不能推出 pinned memory 在其他模型、输入尺寸、设备或并发拓扑下均具有同等收益。V3R 未实现零拷贝、双缓冲、显式传输—计算重叠或跨帧异步执行，因而这些机制不能用于解释当前结果。

## 4.4 尾延迟与适用范围讨论

V3R 在平均指标上表现出有限的正向增量，但尾延迟并未呈现一致方向。V2R 的 P95 和 P99 分别为9.827和11.529 ms，而 V3R 分别为9.842和11.515 ms。与 V2R 相比，V3R 的 P95 增加0.1514%，即数值略高；P99则降低0.1184%，即数值略低。两个百分位的变化方向相反，且变化幅度均较小，因此不能据此得出 pinned staging 能够一致降低尾延迟的结论。

这一结果表明，平均性能改善没有转化为一致的尾延迟改善。V3R 相对于 V2R 同时获得了4.0738%的 FPS 增量和4.0349%的平均延迟降低，但 P95 与 P99 分别向较慢和较快方向变化，尾部行为应判定为混合（mixed）。从一般系统性能角度看，百分位指标可揭示均值未表达的尾部特征 [@dean_barroso_2013_tail_scale]；该文的分布式数据中心机制不用于解释本文单 Jetson 离线回放结果。本文实验没有测量能够识别该差异来源的系统因素，因此不对缓存、操作系统调度、CUDA runtime、DVFS、页迁移或内存控制器行为作事后归因。就本文工作负载而言，pinned staging 的作用应限定为平均性能上的小幅增量，而非稳定的尾延迟优化手段。

综合两级干预，在本文受测配置内，工程优化应结合路径结构与实测影响，优先处理完整数据路径中经测量表明具有较高影响的部分，而不能仅依据结构范围宽窄预测收益。当 V2R 路径已经形成后，仅改变内存暂存策略在本实验中只带来有限的平均增量，并且不能由均值变化推定尾延迟同步改善。该含义只适用于单一 Jetson Orin Nano Super 平台、固定 YOLOv8n INT8 Engine、640×640输入、batch size为1、180幅图像离线回放和当前单帧顺序执行拓扑。本文采用5次独立进程和逐帧描述性统计，没有进行置信区间、假设检验或统计显著性推断；实验也未测量功耗、资源占用、长期耐久性或真实相机输入。因此，结果用于说明该受测配置下的数据路径权衡，不扩展为对其他平台、模型或工业现场运行条件的普适性能结论。
